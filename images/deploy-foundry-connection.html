Deploy Foundry MCP Connection

GitHub Actions workflow — deploy-foundry-connection.yaml — wires MCP OAuth connections for Flight & Hotel servers at the Foundry project level

Trigger

workflow_dispatch

Manual trigger from the Actions tab — run after infrastructure and app deployments are complete

No inputs — reads all values from auto-populated secrets
Step 1

Generate Client Secrets

Create new password credentials on both Foundry MCP app registrations via the Microsoft Graph API (addPassword)

Graph API: POST /applications/{id}/addPassword Masked in CI logs × 2 (Flight + Hotel)
Step 2

Create MCP Connections at Project Level

Deploy OAuth2 MCP connections via ARM REST API at the Foundry project scope — this enables agents to discover MCP tools

ARM PUT: /accounts/{name}/projects/{name}/connections authType: OAuth2 category: RemoteTool flightserver-mcp hotelserver-mcp
Step 3

Patch OAuth Redirect URI

Extract the consent redirect URL from the connection response (global.consent.azure-apim.net/redirect/...) and patch it into the app registration's redirect URIs

Graph API: PATCH /applications/{id} Deduplicates URIs Removes stale consent URIs
🐔
Why a script instead of Bicep? — This is a chicken-and-egg problem: the redirect URL is only known after the connection is created, so it must be patched afterward. Bicep cannot generate secrets via Graph API or deploy connections at the project level.
